PyFE4AI — Python Functional Encryption for Trustworthy AI

Compute on encrypted data. Reveal only the result.

A research-oriented Python library of functional encryption (FE) schemes for AI security and privacy — from single-input inner products to multi-client, threshold, decentralized, and quadratic constructions.

Why PyFE4AI

One entry point — pyfe4ai.create("family/variant", config), then setup / get_decryption_keys / encrypt / decrypt — across the functional-encryption zoo, built for ML workloads.

🧩

Complete FE family coverage

SIFE, MIFE, MCFE, decentralized MCFE, threshold MIFE/MCFE, function-hiding IPE / Multi-IPE, and quadratic FE (SGP, Quad, multi-input MIQFE) — 42 (family, variant) combinations under one roof.

🔐

Six hardness assumptions

DDH (3072-bit groups or the ristretto255 curve), Damgård-DDH (MDDH), Paillier/DCR, LWE, Ring-LWE (lattice lines) and pairings (BLS12-381) — pick the assumption that fits your deployment.

🤖

ML-native adapter

pyfe4ai.ml runs SIFE and MCFE schemes for encrypted linear inference and gradient aggregation, including threshold MCFE over Ring-LWE with its decryption servers in-process. Its wrapper holds the master key and plays every party (one trust domain, for experiments) and by default refuses MIFE aggregation, partial aggregates and label reuse; the other threshold and decentralized variants go through the scheme classes. A quantization toolkit handles float ↔ integer precision.

⚡

Engineered for speed

An optional Rust extension, built by pip install when cargo is available, runs the lattice hot paths, ristretto255 and BLS12-381 pairings with the outputs of the Python reference: an MCFE Ring-LWE round of 10 000 gradient elements under standard takes about 18 ms per client and 7.5 ms to aggregate (v0.3.0: 198 / 280 ms).

🧪

Tested

About 4,100 tests, run in CI with and without the Rust extension (the native code is checked bit for bit against the Python reference), including status-table sync, security-profile and crypto-review regression tests, plus a structured FEError exception hierarchy.

📚

Paper-referenced

Every scheme cites its source construction (PKC'15, CRYPTO'16/'18, ASIACRYPT'18, SCN'20, TCC'21/'22, PKC'22, IACR CiC'24, IEEE TDSC TAPFed, …) in the module docstring. Deviations from the paper are listed in the Scheme Status table.

🛡️

Security profiles & review status

Default parameters are toy: fast and not secure. "security_profile": "standard" selects 3072-bit discrete-log groups (RFC 3526) and DCR moduli, lattice-estimator-sized LWE and Ring-LWE dimensions and stat_param 128, except for pairings, which run on BLS12-381 (about 120–126-bit after the exTNFS attacks; a FESecurityWarning says so), and for ALS16 FullySec-LWE (SIFE, MIFE), threshold MIFE-LWE and dMCFE-Paillier, which it refuses. Of the 42 registered schemes, 34 are reviewed against their papers, 5 are experimental (our own threshold layers and the dMCFE-DDH carry mask), 3 (DDH over ristretto255) are not yet reviewed and none is known to be insecure; get_scheme_status(family, variant) reports each at runtime. Quickstart

Encrypt a vector, hand out a functional key, learn only the inner product. Demo parameters are toy-sized: sec_param is a modulus bit length, not a security level; "security_profile": "standard" selects 128-bit-oriented parameters, except for pairings (BLS12-381, about 120–126-bit) and the schemes it refuses (Security Profiles).

# install
git clone https://github.com/spire-studio/pyfe4ai.git
cd pyfe4ai
conda env create -f environment.yml
conda activate pyfe4ai
# with cargo on the PATH this also builds the optional Rust
# extension (BLS12-381 for the pairing & quadratic FE)
pip install -e ".[test]"

# other pairing curves (charm-crypto): GMP, OpenSSL, PBC first
pip install -e ".[test,pairing]"

# run the core test suite
python -m pytest -m core -q
import pyfe4ai

x, y = [2, 1, 3], [4, 5, 6]

# sec_param = 128 is a toy modulus size: fast, NOT secure. For a
# 3072-bit group pass {"security_profile": "standard", "eta": 3}.
kg, SIFEDDH = pyfe4ai.create("sife/ddh", {"sec_param": 128, "eta": 3})
kg.setup()
pp, sk = kg.get_public_parameters(), kg.get_private_keys()
dk = kg.get_decryption_keys("sid_0",
        credentials={"fusion_weight": y})

ct = SIFEDDH({"precision": 3, "keys": {"pp": pp, "sk": sk}}).encrypt(x)
result = SIFEDDH({"precision": 3, "keys": {"pp": pp}}).decrypt(ct, dk, y)
print(result)  # 31 = ⟨x, y⟩

Built for Privacy-Preserving ML

Functional encryption reveals a chosen function of the data — not the data itself.

🌐 Federated-learning secure aggregation

Clients encrypt local gradients with MCFE-DDH (CDGPP18), the DCR, LWE and MDDH constructions of ABMPSW20, or MCFE-Ring-LWE (BMMS21), which under standard encrypts 10 000 gradient elements in about 18 ms per client with the Rust extension (0.35 s in pure Python); the aggregator's functional key decrypts only the weighted sum. dMCFE variants remove the key authority, and tMCFE variants (TAPFed-style) split decryption across t-of-s servers that are assumed honest-but-curious; their LWE, Ring-LWE and pairing threshold layers are experimental. Check the Scheme Status before choosing one.
